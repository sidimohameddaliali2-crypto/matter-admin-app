# Complete native preservation proof

The [parity operator](../../.github/scripts/driver-audit-native-parity.mjs) is read-only for application and source data. It does not initialize collections, invoke source endpoints, execute the migration CLI, verify authority in the database, activate authority, or change process configuration. It writes only owner-private verification receipts and its operator lock. Fixture success is not production verification.

The public inputs are the transfer session UUID, native profile SHA-256, independent final closure-proof SHA-256, reviewed deployed app commit and an optional RSA public recipient for the exact private receipt. All private paths and application imports are derived on the host. The operator checks the Linux checkout, unchanged tracked verification dependencies, stopped source/sync workers, managed sync path, verified transfer provenance, actual target database and staging authority. It rechecks the actual collector census and original bootstrap before and after verification.

The existing private transfer session must contain its original `session.private.json`, `received.private.json`, pinned `profile.private.json`, original profile-referenced files and `closure-proof.private.json`. The latter is a private independent source audit, not output from the partial migration CLI. It must use this contract:

- `version: 1`, `status: "final-driver-audit-source-closure"`, `verified: true`, `complete: true`.
- `sourceRevision`, `collectorRootsSha256`, and `bootstrap` containing the actual original `collectorRevision`, `manifestSha256`, `sourceBasis` and `seedSha256`. The actual managed seed and full census must agree. A reconstructed fixture or an assumed bootstrap cannot satisfy this requirement.
- `origin` containing pinned `sourceSnapshotSha256`, `restoreVerificationSha256`, `originalArchiveInventorySha256` and `sourceDumpSha256` from the independently verified original snapshot and preserved backup. An optional `acceptedNativeImportSha256s` array explicitly pins earlier known native import profiles whose unchanged records were reused; it must come from the reviewed import history, not be inferred from arbitrary target metadata. The current profile and its pinned `previousImportSha256` are accepted automatically.
- `inputs` containing the profile's exact `{file,sha256}` references for `documents`, `receipts`, `historical`, `objects`, `reviewContexts`, `reviewDependencies` and `bookkeepingBackup`. Final receipts must use `receiptInput: "selected"` and the actual collector-root selection proof.
- `archive: {inventorySha256,objects,bytes}`. The inventory hash covers UTF-8 JSONL of unique `{key,bytes}` records sorted by key, with one final newline. It identifies the complete independently derived original physical union, not merely a convenient supplied sample.
- `coverage.photos: {objects,bytes,identities}`, `coverage.gps: {objects,bytes,snapshotRefs}`, `coverage.raw: {identities}`, `coverage.results: {assessmentRows,historicalRows}` and `coverage.reviewEvents`. These are pinned independent source-closure counts. The verifier labels that provenance and does not pretend to independently reconstruct source completeness from the target inventory.
- `gaps: {reviewContexts: [], images: [], logicalPaths: []}`. Review context/image entries are original SHA-256 identities; logical path entries are strings. Existing unavailability stays explicit. Source-missing context identities must exactly match the original human journals and imported availability records.
- `inlineReferences: []`. Each entry contains `objectKey`, RFC 6901 `pointer`, `encoding` (`base64`, `json` or `text`), original `sha256`, `bytes` and `kind` (`gps` or `source`). Inline files are verified inside their original retained containers without manufacturing duplicate archive objects.

The operator compares every original current body and revision; all selected receipt bodies, events, hashes and original timestamp strings; all historical bodies, namespaces and derived IDs; all human review events and context/dependency indexes. Counts must match the complete native collections. Missing imported provenance fails. Exact bytes are compared without JSON reserialization or JavaScript timestamp conversion. All original context dependencies must be inside the complete physical union. Protected staged archive extras are counted separately and never pruned.

Small native record indexes are read in bounded cursors, then original text payloads are freshly checked with at most four concurrent reads and bounded batches. Fingerprints retain original input order. This avoids a separate remote metadata lookup for every history row during the final window; it does not replace body comparisons with metadata flags.

The initial archive verification reads every declared immutable native object and checks size and SHA-256 against the original source key. It captures native file references and referenced chunk IDs/sizes before and after the scan. The attestation binds those roots, the complete inventory, target database identity and exact reader/verifier implementation hashes.

Avoid repeating this full scan when the already-authorized migration CLI `verify` pass has completed the same full object iteration. Capture `captureNativeDriverAuditArchiveMetadata` before and after that exact pass, then pass its raw completed receipt to the pure `createDriverAuditNativeCliByteAttestation` constructor with the actual CLI/archive implementation hashes, hash-pinned `sourceProfileBytes`, and its hash-pinned `sourceObjectsBytes`. The constructor verifies that this actual profile's object file describes the same canonical inventory as the before/after metadata. Reuse by a later profile requires that same canonical inventory. The constructor does not execute the CLI or write the database. Save the result owner-private as `archive-bytes-<inventory SHA>-<metadata SHA>.private.json` under the transfer root. An old partial CLI receipt without the matching profile/object bytes, metadata captures, and exact implementation pin cannot be upgraded after the fact.

The verifier uses the actual census's exact historical receipt bindings through the same reviewed receipt selector as the migration CLI. Inline GPS and photo references are grouped by original container; each container is read and released once, keeping decoded data bounded.

The migration CLI itself initializes native bookkeeping, so this read-only operator never launches it. The caller separately owns any authorized CLI operation. Its completed object hash iteration plus the final independent closure can establish original GPS/photo byte preservation; its partial receipt alone cannot establish complete closure or activation readiness.

A later final-window run may reuse the full attestation only when the entire declared immutable inventory and native file/chunk metadata roots still match the same target and implementation. It always freshly compares current documents, receipts, history, journals, contexts, inline originals, staging authority and actual census. The receipt records the original full-byte verification time, method and implementation hash, and reports zero freshly scanned full-object bytes when reusing it. It never labels metadata-only reuse as a fresh full byte scan.

Only the resulting `completeByteParity.verified` result is suitable for the separately controlled `verifyDriverAuditMongoAuthority` callback. That authority operation and the final writer/review fences remain the caller's responsibility. The parity operator returns `authorityChanged: false` and `activationPending: true`; it does not perform them.

The handoff bridge prints a bounded public summary. For private release assembly, provide the optional RSA public recipient to receive `sealedReceipt` in the same verification job. Decrypt it owner-private and verify the exact saved receipt bytes, SHA and application/session/profile/closure bindings; reconstructing a receipt from the public summary changes its identity. The separate `export-native-controls` operation retrieves only fixed current profile, source/sync configuration, prepared settings plan and an explicitly selected qualification receipt. Its encrypted export preserves partial qualification as partial and does not certify release readiness.

Local validation: `node --test .github/scripts/driver-audit-native-parity.test.mjs .github/scripts/driver-audit-native-import.test.mjs`, followed by the server `npm test` suite. Keep fixture, actual host parity and production staff/source journey acceptance distinct.
